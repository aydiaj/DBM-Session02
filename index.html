1 · Prepare the connection settings

First, identify the SQL Server instance, the database, and the authentication method. Store these settings in a connection string.

At this stage, we have only prepared information. We have not created a connection object, contacted SQL Server, or executed any SQL.

What goes in?

A connection string tells the provider where to connect and how to authenticate. The SQL text tells SQL Server what to calculate. 

SELECT COUNT(*)
FROM dbo.Students;

What comes back?

One number: how many rows the Students table contains. ExecuteScalarAsync() retrieves the first column of the first returned row.

4 rows in this example’s starter table

If the table contains additional records, the returned count will be different.

Preparing is different from opening

Writing a connection string prepares the settings. Creating a SqlConnection creates an object that holds those settings. Calling OpenAsync() attempts to establish the actual database connection.

Similarly, creating a SqlCommand prepares an instruction. Calling an execution method, such as ExecuteScalarAsync(), sends it for execution.

One keyword, two different uses: using

using Microsoft.Data.SqlClient; lets us access classes from that namespace without writing their full names. The same keyword, using, can appear elsewhere in C# for a completely different purpose: automatically releasing resources, such as a database connection, when they are no longer needed. await using performs this cleanup asynchronously.

Concept simulation · does not connect to SQL Server

Follow the connection’s lifetime

No connection object has been created.
What about Close, Dispose and finally?

Close() closes the logical connection. Dispose() / DisposeAsync() also handles resource cleanup. A using scope gives automatic cleanup when control leaves the scope, including after an exception. You do not need a second manual Close after await using.

Why using is safer than “remember to close”

Conceptually, resource scopes arrange cleanup with try/finally logic. A finally block runs as control leaves try, even when an exception occurs. The compiler supplies the cleanup for using; do not add this as a second connection task.

C# · explanatory alternative, not an extra TODO
var connection = new SqlConnection(connectionString);
try
{
    await connection.OpenAsync();
    // Use the connection here.
}
finally
{
    await connection.DisposeAsync();
}

With connection pooling enabled, disposing normally returns the physical connection to the pool for reuse. It does not necessarily tear down a network socket. Keep Console input outside open-connection scopes.

Troubleshoot the evidence

Server not found / timeout: check the exact instance name, SQL Server service and device/network availability.

Login failed: check the authentication method and account permissions.

Cannot open database: check the database name, setup script and permissions on this same instance.

Certificate error: confirm the approved local classroom configuration with your instructor.

C# · replacement block
            // TODO 03 — Completed: multiple rows.
            await using (var connection = new SqlConnection(connectionString))
            {
                await connection.OpenAsync();
                const string sql = "SELECT StudentId, FullName FROM dbo.Students ORDER BY StudentId;";
                using var command = new SqlCommand(sql, connection);
                await using var reader = await command.ExecuteReaderAsync();
                while (await reader.ReadAsync())
                {
                    int id = reader.GetInt32(0);
                    string name = reader.GetString(1);
                    Console.WriteLine($"{id}: {name}");
                }
            } // Reader is disposed before connection (reverse declaration order).
const string sql
Stores the fixed SQL text. Its SELECT order determines the column ordinals used below.
await command.ExecuteReaderAsync()
Executes the query and gives a SqlDataReader for its result.
await using var reader
Ensures the reader is disposed before the enclosing connection.
while (await reader.ReadAsync())
Moves to the next row. true means a row is available; false ends the loop. The reader starts before the first row.
reader.GetInt32(0)
Reads the first selected column, StudentId, as an integer. Column ordinals are zero based.
reader.GetString(1)
Reads the second selected column, FullName, as a string. These supplied columns are NOT NULL.
Inside the loop
Map the current row’s values to C# variables, then print them. ReadAsync advances; typed getters read values from that current row.

How do I choose the correct getter?

Check the column types in SSMS before choosing a reader method. The getter must match the SQL type returned by the query:

  • int → GetInt32()
  • bigint → GetInt64()
  • nvarchar or varchar → GetString()
  • decimal → GetDecimal()

These getters do not automatically convert between types. Using the wrong getter can cause an InvalidCastException.

What if I do not know the type yet?

GetValue() retrieves the value as an object, without choosing a typed getter: 

object value = reader.GetValue(0);
Console.WriteLine(value);

For this lab, we know the column types, so use GetInt32() for StudentId and GetString() for FullName.

Why not concatenate input?

Concatenation mixes values into SQL syntax. Typed parameters keep the instruction and input separate. They do not replace table or column names. Validation checks that input fits the application’s rules; parameters control how that value is supplied to SQL Server.

Review: classes we used

Recall where each class appeared in the application and explain its responsibility.

  • SqlConnection — represents the database connection. Creating the object prepares it; OpenAsync() opens it.

  • SqlDataReader — reads result rows. ReadAsync() advances to the next row.

More ADO.NET Classes — Optional Preview

The following classes extend the picture beyond the four classes used in this practical. You do not need to implement them in this lab.

SqlTransaction

Groups database operations into a transaction, allowing the changes to be committed together or rolled back.

What does “in-memory” mean?

An application can load data from a database and keep a copy in its own memory. It can then work with that copy without keeping the database connection open throughout that work.

DataTable and DataSet

DataTable holds rows and columns in memory. DataSet can contain several DataTable objects and relationships between them. Changes to these objects do not automatically update SQL Server.

SqlDataAdapter

Uses connections and commands to transfer data between a database and in-memory tables. Transferring changes back to the database requires database communication again.
